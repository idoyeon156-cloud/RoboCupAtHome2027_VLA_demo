# 물체가 바뀌었을 때: 숫자 바꾸고 다시 실행하기

**① 파일 열기 → ② 숫자 바꾸기 → ③ 저장 → ④ 다시 실행**

## ① 이 파일 하나를 엽니다

`SW/cereal_pour/config/cereal_task.yaml`

ZIP을 풀어 쓰면, 압축을 푼 폴더 안의 `config/cereal_task.yaml`입니다.

**기존 줄의 숫자만 고칩니다. 같은 항목을 파일 끝에 추가하지 않습니다.**

## ② 바뀐 물체의 숫자를 고칩니다

### 그릇 위치가 바뀌었다면 → `bowl:` 아래

```yaml
  bottom_center_world_m: [0.49, 0.115, 0.0]
```

숫자는 **[앞으로, 왼쪽으로, 위로]**, 단위는 **m**입니다.

- 기준점: 두 팔 베이스 중심의 한가운데. 높이 0은 베이스가 고정된 면.
- 재는 곳: 물체의 **바닥 한가운데**.
- 왼팔 쪽이면 두 번째 숫자는 `+`, 오른팔 쪽이면 `-`.
- 베이스와 같은 면에 놓으면 세 번째 숫자는 `0.0`.
- **1cm=`0.01`, 45cm=`0.45`, 50cm=`0.50`**.

예: 그릇을 앞으로 45cm에 놓았다면 첫 번째 숫자만 바꿉니다.

```yaml
  bottom_center_world_m: [0.45, 0.115, 0.0]
```

### 그릇 크기가 바뀌었다면 → 같은 `bowl:` 아래

```yaml
  diameter_m: 0.170                         # 지름 17cm
  height_m: 0.055                           # 높이 5.5cm
  grasp_offset_world_m: [0, 0.085, 0.035]   # 왼쪽 8.5cm, 바닥에서 3.5cm를 잡음
```

둥근 그릇의 지름이 20cm가 되었다면:

```yaml
  diameter_m: 0.200
  grasp_offset_world_m: [0, 0.100, 0.035]
```

왼쪽 가장자리까지의 거리도 지름의 절반인 10cm로 바꿉니다. 잡는 높이는 계속 3.5cm입니다. 새 그릇의 높이가 바뀌면 `height_m`도 바꾸고, 잡는 높이가 그릇 높이보다 높지 않게 합니다.

### 상자 위치·크기가 바뀌었다면 → `box:` 아래

```yaml
  bottom_center_world_m: [0.47, -0.20, 0.0] # 상자 바닥 중심 위치
  size_m: [0.08, 0.06, 0.22]               # 앞뒤 8cm, 좌우 6cm, 높이 22cm
  grasp_offset_world_m: [0, 0, 0.08]       # 바닥에서 8cm를 잡음
  outlet_in_object_m: [0.04, -0.03, 0.22]  # 내용물이 나오는 점
```

`size_m`의 앞뒤·좌우는 현재 `rpy_deg: [0,0,0]`인 배치 기준입니다. 상자를 회전시키면 상자 자체의 X·Y 크기를 뜻합니다.

상자가 앞뒤 10cm, 좌우 8cm, 높이 25cm가 되고 같은 모서리로 붓는다면:

```yaml
  size_m: [0.10, 0.08, 0.25]
  outlet_in_object_m: [0.05, -0.04, 0.25]
```

크기와 함께 실제 붓는 구멍 위치도 맞춥니다. 구멍 위치는 상자 바닥 중심에서 잽니다.

### 잡는 폭도 바뀌었다면 → 해당 물체 아래

```yaml
  gripper_open_opening_mm: 80    # 접근할 때 벌리는 값
  gripper_closed_opening_mm: 60  # 잡을 때의 값
```

이 예시는 상자 값입니다. 그릇은 현재 `30`, `10`입니다. **이 두 항목만 mm**이며 현재 모델의 범위는 `0~100`, 여는 값은 잡는 값보다 커야 합니다.

드라이버의 총 개방 이동량이므로 실제 물체 두께와 반드시 같은 숫자는 아닙니다. 실제 그리퍼 눈금에 맞춥니다. 크기만 수정하면 잡는 폭까지 자동으로 바뀌지는 않습니다.

### 들어 올려 붓는 자리까지 바꾸려면 → `pour:` 아래

```yaml
  bowl_bottom_center_world_m: [0.49, 0.115, 0.10]
```

이 줄은 **파지 후 들어 올린 그릇의 자리**입니다. 처음 그릇이 놓인 자리인 `bowl:`과 별도입니다. 여기의 Z=`0.10`은 들어 올린 높이이며, 처음 바닥 높이 Z=`0.0`과 다릅니다.

## ③ 저장합니다

편집기에서 저장합니다. `nano`라면 `Ctrl+O` → `Enter` → `Ctrl+X`입니다.

**조인트 각도나 생성된 경로 파일은 직접 고치지 않습니다.**

## ④ 껐다가 다시 실행합니다

돌아가는 프로그램을 `Ctrl+C`로 종료합니다. 로봇이 동작 중이면 먼저 정지한 상태에서 설정을 바꿉니다.

`run_cereal_rviz.sh`가 있는 폴더에서 화면 확인:

```bash
bash run_cereal_rviz.sh
```

프로그램이 바뀐 숫자를 읽어 **새 관절각 계산 → 경로 생성 → 충돌 검사 → 화면 재생**을 수행합니다. 손이 안 닿거나 충돌하면 오류를 내고 실행을 중단합니다.

실물용에도 같은 설정을 적용하려면 실물 프로그램을 종료한 뒤 다시 실행합니다. 실제 장착 모델 확인을 마치고 기존 명령 전달 모드를 쓰는 경우:

```bash
bash run_cereal_real.sh enforce:=true geometry_confirmed:=true
```

실물용도 같은 설정을 읽고 경로를 다시 계산합니다. 실행기 기동 후 실제 동작은 기존 prepare → start 순서입니다.

**YAML 변경만으로 별도 수동 빌드는 필요 없습니다. 실행기가 알아서 처리합니다. 켜 둔 프로그램에 저장만 해서는 적용되지 않습니다.**

시뮬 ZIP과 실물 ZIP을 서로 다른 폴더에 풀었다면, 수정한 `config/cereal_task.yaml`을 두 폴더에 똑같이 넣습니다. 같은 폴더에서 시뮬·실물을 실행하면 한 번만 수정하면 됩니다.

실행 직후 가드에 피드백 시간 초과 잠금이 남아 있으면 양팔 피드백을 확인한 다음 아래 두 서비스를 호출합니다. 리셋은 조건이 충족될 때만 성공합니다.

```bash
ros2 service call /collision_guard/reset std_srvs/srv/Trigger '{}'
ros2 service call /moveit_guard/reset std_srvs/srv/Trigger '{}'
```

이미 알파 자세라면 prepare를 다시 보내지 않고 start를 사용합니다. 영점 자세라면 기존 prepare → 도착 확인 → start 순서입니다.
