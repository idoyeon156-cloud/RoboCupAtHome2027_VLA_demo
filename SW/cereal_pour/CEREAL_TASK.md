# YAML 기반 파지·붓기 경로 — RViz와 실물 배포용 공통

`config/cereal_task.yaml`이 물체·파지점·알파 자세·속도·붓기 목표의 입력입니다. `model/cereal_task_sequence.yaml`은 솔버 출력이므로 직접 수정하지 않습니다. 양팔 알파는 `[0, 90, 0, 0, -70, 0]°`이며 J2와 J5는 같은 시간에 출발하고 도착합니다. URDF의 기존 ±1.22rad 반올림 한계는 정확한 ±70°로 맞췄습니다. 실물 관절 한계도 이 범위를 지원하는지 확인해야 합니다.

## 좌표와 설정

world 원점은 두 팔 베이스 원점의 가운데이며, X는 전방, Y는 왼팔 방향, Z는 위입니다. 단위는 m, 각도는 이름에 `_deg`가 있으면 도입니다. 물체 위치는 모두 **바닥 중심**입니다. 물체가 작업대 위에 있다면 Z에는 작업대 상면 높이를 넣습니다. 기둥·마운트 설치는 `config/robot.yaml`에서 관리합니다.

현재 예시값은 다음과 같습니다. 그릇과 상자 바닥은 베이스 장착면과 같은 world Z=0입니다. 실물에서 X/Y와 크기를 측정해 변경하세요. `pour.bowl_bottom_center_world_m`의 Z=0.10은 파지 후 들어 올린 높이이며 초기 배치 높이와 다릅니다. 테이블 형상은 별도로 모델링하지 않았습니다.

```yaml
bowl:
  bottom_center_world_m: [0.49, 0.115, 0.0]
  diameter_m: 0.170
  height_m: 0.055
  grasp_offset_world_m: [0, 0.085, 0.035]
box:
  bottom_center_world_m: [0.47, -0.20, 0.0]
  size_m: [0.08, 0.06, 0.22]
  grasp_offset_world_m: [0, 0, 0.08]
```

그릇은 world X=49cm입니다. 왼팔 파지점은 바닥 중심에 `[0,+8.5,+3.5]cm`, 오른팔 파지점은 상자 바닥 중심에 `[0,0,+8]cm`를 더합니다. 파지 방향(`gripper_rpy_in_object_deg`), 개방/폐쇄 폭, TCP도 같은 파일에 있습니다. 현재 그릇은 접근 가능성과 손목 간섭을 고려한 `[0,110,-15]°` 방향을 사용합니다. 크기와 파지 폭·오프셋은 서로 맞게 설정하세요. 물체 크기만 바꾸면 접촉점까지 자동 추정하는 구조는 아닙니다.

## 현재 실행

실물 접촉 사고 조사 중이며 실물 자동 실행은 차단되어 있습니다.
[SIM_START_KO.md](SIM_START_KO.md)의 `bash run_cereal_rviz.sh`로 시뮬을 먼저 확인합니다.
현재 시뮬은 자동 반복하지 않으며, 영점에서 출발해 두 가드를 통과한 가상 피드백으로 표시하고 영점에 복귀합니다.
설정 변경 시 MoveIt 경로를 새로 계획합니다. 실패하면 중단하고 이전 경로로 진행하지 않습니다.

## 솔버와 검증 범위

Pinocchio FK + SciPy 수치 IK로 목표 관절각 후보를 구하고, MoveIt OMPL RRTConnect가 경로를 생성합니다.
MoveIt Bullet 메시 검사와 feasibility callback의 보호 구 거리/물체/파지 물체 조건을 계획 중 적용합니다.
실행 구간 보간도 같은 조건으로 확인합니다. 자체 RRT와 무검사 직선 경로 우회는 제거했습니다.
계획/실행은 같은 모델과 semantic 설정을 사용하며, 같은 팔 전체 제외를 제거하고 고정 몸체·인접 관절 및 같은 그리퍼의 두 손가락 맞닿음만 제외합니다.
양팔 간, 비인접 같은 팔, 기둥 충돌을 검사합니다. 물체의 의도한 자기 손가락 접촉만 별도 허용합니다.

실시간 두 가드는 로봇과 고정 기둥을 검사합니다. 이동 물체는 사전 경로 검사에 포함되며 실시간 센서로 갱신하지 않습니다. 실제 그릇 형상, D405 본체·케이블, 테이블, 물체 미끄러짐은 현재 모델 범위 밖입니다.

IK 불가·충돌·시간 초과이면 생성 파일을 교체하지 않고 실행을 중단합니다. 오래된 경로로 자동 진행하지 않습니다. 경로 파일을 명시하는 `sequence_path:=...`는 고급/기존 경로용이며 자동 재생성을 건너뜁니다.

```bash
# 실행 전 경로만 재계산/검사
.venv/bin/python tools/plan_cereal_task.py
.venv/bin/python tools/plan_cereal_task.py --check
```

저장소 루트의 가상환경을 쓰면 `.venv/bin/python` 대신 `../../.venv/bin/python`을 사용하세요. 기존 고정 관절각 빈 그리퍼 시퀀스는 `CEREAL_POUR.md`에 별도 기록되어 있습니다.

## 과거 버전의 검사 기록 — 새 MoveIt 구현에 대한 결과가 아님

2026-11-12: ROS 2 Humble 세 패키지 빌드 완료. 기본 경로 49개 경유점과 1,800개 보간 상태 검사 통과. ROS 테스트에서 RViz 물체/관절 발행, 실물 노드의 prepare→start→복귀, MoveIt 차단 시 보간 정지, 실제 MoveIt/FCL 서비스의 전체 경로 250개 표본을 확인했습니다. 물체 X 좌표를 바꿨을 때 관절각 재계산과 도달 불가 설정에서 기존 출력 보존도 확인했습니다. 하드웨어 드라이버는 실행하지 않았습니다.

배치 높이 수정 후 전체 경로의 이동 메시를 검사했으며 장착면(Z=0) 아래로 내려가는 상태가 없음을 확인했습니다.

실물 가드를 시작할 때 생긴 피드백 시간 초과 잠금은 유효한 양팔 피드백이 들어온 뒤 명시적으로 리셋합니다. 현재 자세가 이미 알파이면 prepare 대신 start를 사용합니다. 0.05°의 관측 경계 오차 처리와 재개 거리 2cm 설정은 REAR_PROFILE.md를 참고하세요.
