## 충돌 원인: 확인된 사실과 미확정 사항

실제 양팔 접촉과 충돌 방지 실패는 사용자 관찰로 확인됐습니다. 다만 기존 자료로는
접촉을 감지하지 못했는지, 감지했지만 제어기가 접촉 전에 멈추지 못했는지 확정할 수 없습니다.

따라서 남은 조사 범위는 외곽 형상·실물 좌표 대응, 접촉 순간 검사 입력/상태,
검출 이후 최종 명령과 실제 정지 시점입니다. 기존 자료만으로 이 중 하나를 단독 원인으로 지정할 수 없습니다.

## MoveIt 경로를 RViz에서 보는 명령

```bash
cd "/home/doyeonlee/문서/ChatGPT/VLA 공부/RoboCupAtHome2027_VLA_demo/SW/cereal_pour"
bash run_cereal_rviz.sh
```

이 명령은 필요한 ROS 패키지를 빌드하고, 유효한 캐시가 없으면 MoveIt 경로를 생성합니다.
목표 IK는 Pinocchio FK + SciPy, 경로 탐색은 native MoveIt PlanningPipeline + OMPL RRTConnect,
충돌 검사는 Bullet 메시 및 거리·물체·파지 물체 조건의 feasibility callback입니다.
실행 보간도 검사하며 계획 실패 시 기존 파일을 대신 실행하지 않습니다.

실행 연결: 시퀀스 → 거리 가드(enforce) → MoveIt 메시 가드(enforce) → 이상적 가상 드라이버 → RViz.
영점 → 양팔 알파 `[0,90,0,0,-70,0]°` → 파지 → 붓기 → 내려놓기 → 영점 복귀를 자동 수행합니다.
알파에서 별도 start는 필요 없습니다. 완료 표시는 `SIMULATION COMPLETE`입니다.
계획만 실패하거나 도중 정지하면 전체 시퀀스 완료가 아닙니다. 최신 소스의 성공은 미확인입니다.

## 실물 전체 시퀀스의 명령 인터페이스

현재는 사고 차단 파일 `REAL_MOTION_HOLD_KO.md`가 있어 아래 실물 시작 명령은 거부됩니다.
또한 이 조사 시점에 `model/last_completed_simulation.json`이 없어 완료한 시뮬 경로도 없습니다.
아래는 현재 코드에 구현된 인터페이스의 설명이며, 차단 해제나 즉시 실물 실행 지시가 아닙니다.

실행 조건이 해결된 뒤의 상주 프로세스 준비는 각각 별도 터미널에서 합니다.
세 터미널 모두 같은 작업 폴더에서 실행하며 CAN 인자는 실제로 확인한 연결을 사용해야 합니다.
다음 can0/can1은 기존 기본값으로, 물리 대응을 새로 확인한 결과가 아닙니다.

```bash
# 터미널 1: 드라이버. 자동 활성화 시 그리퍼가 닫힙니다.
bash run_piper_driver.sh can0 can1
```

```bash
# 터미널 2: 두 가드와 시퀀스 실행기. 이 명령만으로 시퀀스를 시작하지 않습니다.
bash run_cereal_real.sh enforce:=true geometry_confirmed:=true
```

```bash
# 터미널 3: 계획된 영점에서 전체 동작을 한 번 요청
bash run_real_control.sh run
```

`run`은 피드백/모드 확인 → 최초 두 가드 리셋과 상태 확인 → 계획된 영점 확인 →
알파 → 파지·붓기·내려놓기 → 알파 경유 → 영점 복귀를 연속 수행합니다.
단계마다 prepare/start/home를 추가로 입력하지 않습니다. 영점에는 관절각뿐 아니라 그리퍼 폭도 포함됩니다.
`Finished; holding return_home`가 전체 완료입니다. 중간 차단 시 자동 재리셋·재개하지 않습니다.

실물 파이프라인은 시뮬 완료 경로의 파일·모델·소스·속도 지문을 확인하며 새 경로를 임의 재계획하지 않습니다.
다른 기기로 옮긴 배포본은 그 폴더에서 시뮬을 다시 완료해야 합니다. 완료 기록은 절대 경로에 묶입니다.
`geometry_confirmed:=true`는 사용자가 전달하는 플래그이며 실제 형상을 자동 측정하거나 검증하지 않습니다.
현재 실물은 MoveIt FollowJointTrajectory에 직접 궤적을 전달하지 않고 자체 실행기가 관절 목표를 보냅니다.

## 실물 충돌 방지의 적용 범위

계획의 양팔/고정 환경 메시·거리·물체 조건과, 실행 중 거리 가드 → MoveIt 메시 가드를 함께 사용합니다.
실행 가드는 센서 피드백과 다음 목표 사이를 검사합니다. 계획 단계의 물체·파지 물체 조건 전체가
실행 가드에서 실시간 재검사되는 구조는 아니며, 이동 장애물의 센서 기반 PlanningScene 갱신도 없습니다.
실물 좌표와 모델이 다르거나 실제 구동이 검사한 보간에서 벗어나면 MoveIt 계획 통과만으로 접촉 방지를
보장할 수 없습니다. 이 문제의 원인과 제동 효과가 확인되지 않았으므로 실물 안전 검증 완료로 표현하지 않습니다.
