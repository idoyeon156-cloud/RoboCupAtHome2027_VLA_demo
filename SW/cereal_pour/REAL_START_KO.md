# 실물: 영점 → 알파 → 붓기 → 영점 복귀

세 터미널 모두 **이 파일이 있는 `SW/cereal_pour` 폴더**에서 시작합니다.
드라이버와 실물 패키지는 계속 켜둡니다. 중복 실행하지 않습니다.
왼팔 CAN0 / 오른팔 CAN1 배선 기준이며 USB를 옮겼다면 실제 팔과 포트를 확인합니다.

## 권장: 영점에서 명령 한 번으로 전체 실행

아래 1·2번으로 드라이버와 실물 패키지를 먼저 실행해 둡니다.
양팔 관절과 그리퍼가 계획된 영점 상태일 때 터미널 3에서:

```bash
bash run_real_control.sh run
```

이 명령은 피드백 검사 → 두 가드 초기 리셋 및 3초 확인 → 영점 확인 →
알파(감속 접근) → 파지·붓기·내려놓기 → 알파 경유 → 영점 복귀를 연속 실행합니다.
알파에서 별도의 `start` 명령을 기다리지 않습니다.
`Finished; holding return_home`이면 전체 완료입니다.
영점이 아니면 이동 요청은 거부됩니다. 현재 자세를 영점으로 저장하지 않습니다.
중간 오류 시 전체를 정지하며 자동 리셋·재시도하지 않습니다.
아래 `ready / prepare / start`는 단계별 진단용으로도 계속 사용할 수 있습니다.

## 1. 터미널 1: 드라이버

```bash
bash run_piper_driver.sh can0 can1
```

CAN이 꺼져 있으면 활성화할 명령을 표시하고 종료합니다. 그 명령을 실행한 뒤 다시 실행합니다.
자동 활성화 시 그리퍼가 닫힙니다. 이 실행기는 영점 이동·영점 재설정을 하지 않습니다.
이 실행기는 설치된 드라이버의 로컬 복사본(`build/driver_overlay`)을 만들고,
관절 명령·피드백의 각도 변환을 정확한 `math.pi` 기준으로 맞춥니다.
원본 `/home/doyeonlee/piper_ros`는 수정하지 않습니다. 적용하려면 드라이버 재시작이 필요합니다.

## 2. 터미널 2: 실물 패키지

```bash
bash run_cereal_real.sh enforce:=true geometry_confirmed:=true
```

빌드와 시작이 끝날 때까지 기다립니다. 시작만으로 팔을 이동하지 않습니다.
이 명령은 조인트 거리 가드와 MoveIt convex 메시 가드를 함께 실행합니다.
실물 실행 기본값은 `joint_speed_scale:=1.5 driver_speed_ratio:=20`입니다.
기본 설정의 관절 목표 변화율 15°/s에 1.5배를 적용해 22.5°/s로 보간하며,
두 가드가 전달하는 드라이버 속도 비율은 기존 10에서 20으로 올립니다.
그리퍼 목표 변화율과 힘 설정은 유지합니다. 실제 속도가 정확히 1.5배나 2배가
된다는 의미는 아닙니다. 알파 J5의 마지막 5° 감속은 별도로 유지합니다.

## 3. 터미널 3: 피드백 검사와 안전장치 리셋

```bash
bash run_real_control.sh ready
```

양팔 피드백과 프로그램 상태가 3초 연속 정상일 때만 두 안전장치 리셋을 요청합니다.
`PASS`는 피드백·시각·실행 모드 검사 결과이며 잠금 해제를 뜻하지 않습니다.
두 서비스의 `True` 응답에 이어 `READY: 두 안전장치 잠금 해제 후 3초 연속 유지 확인`까지 확인합니다.
실패하면 이동 명령을 요청하지 않고
어느 팔의 피드백·시각 차이·프로그램 상태가 잘못됐는지 표시합니다. 서비스가 없거나
응답하지 않으면 제한 시간 후 종료하므로 무한히 기다리지 않습니다.

## 4. 같은 터미널: 현재 자세 → 영점

양손에 물체가 없는 상태에서 실행합니다.

```bash
bash run_real_control.sh home
```

현재 피드백에서 계획된 초기 자세로 관절 공간을 보간하며 두 가드를 모두 통과합니다.
관절 목표 변화율은 최대 5°/s입니다. 먼저 현재 그리퍼 폭을 유지하며 관절을 이동하고,
그 뒤 그리퍼를 계획된 초기 폭(현재 양쪽 0mm)으로 맞춥니다(최대 5mm/s).
`Finished; holding home`까지 기다립니다. 현재 자세를 새 영점으로 기록하지 않습니다.
장애물 우회 경로를 새로 찾는 명령은 아니므로 경로가 막히면 정지합니다.
정지 후 자동 리셋·재시도하지 않습니다. 물체를 잡은 상태의 복구용으로 사용하지 않습니다.

## 5. 같은 터미널: 영점 → 알파

```bash
bash run_real_control.sh prepare
```

양팔 알파는 `[0, 90, 0, 0, -70, 0]°`입니다.
실물에서 J5 -70.193°의 일시적 초과가 기록돼 알파 접근 감속을 추가했습니다.
이후 실물 로그에서 알파 이동 23.2초가 확인돼, 전체 구간의 5°/s 제한을 제거했습니다.
기본 관절 목표 변화율은 설정값×실물 속도 배율(현재 22.5°/s)을 사용하고, 알파 및 복귀 알파에서
J5가 목표까지 5° 이내일 때만 J5 목표 변화율을 최대 1°/s로 제한합니다.
관절 간 보간은 동기화되므로 이 마지막 구간에서는 다른 관절도 함께 느려질 수 있습니다.
목표각·관절 제한·J5 측정 허용폭 0.15°는 유지합니다. 이 조치가 실물 오버슈트를
해결했는지는 아직 검증하지 않았습니다. 실물 기본 드라이버 속도 비율은 20입니다.

추가 실물 로그에서 `bowl_open`은 6.5초 제한으로 시간 초과됐습니다. 당시 목표·실제 폭
기록이 없어 그리퍼가 느린지, 정지했는지, 가드 대기로 명령이 막혔는지는 확정하지 못했습니다.
그리퍼 이동 단계에는 최소 20초의 단계 제한을 적용하되, 실제 폭이 목표 방향으로
0.25mm 이상 줄어드는 진행이 3초 동안 없으면 원인 분석용 목표·명령·측정값과 가드
상태를 표시하고 정지합니다. 전체 명령 대기 180초와 통신 신선도 제한은 유지합니다.
실행 중 `motion_progress`를 매초 기록합니다. 사용자의 요청에 따라 이 변경 후
추가 테스트·가상 검증·실물 이동을 실행하지 않았습니다.
`Finished; holding alpha`가 나와야 도착입니다. `Sequence started`만으로 도착한 것이 아닙니다.

## 6. 같은 터미널: 붓기 → 내려놓기 → 영점 복귀

```bash
bash run_real_control.sh start
```

`Finished; holding return_home`가 나오면 완료입니다.

## 멈췄다면

```bash
bash run_real_control.sh status
```

표시되는 `detail`과 두 안전장치의 `reason`을 확인합니다. 중간 자세에서 멈췄다면
`prepare`를 반복하지 않습니다. 이 명령은 영점에서 시작하는 경로이며 임의 자세를
복구하는 명령이 아닙니다. 시간 초과·충돌 정지 후 자동 리셋이나 자동 재개는 하지 않습니다.

목표 전송을 명시적으로 멈추려면:

```bash
bash run_real_control.sh stop
```

이것은 소프트웨어 목표 전송 정지이며 하드웨어 비상정지를 대신하지 않습니다.

## 이번 오류와 수정 범위

2026-11-13 추가 실물 읽기 진단: 양팔이 관절 영점인 상태에서 오른쪽 닫힌 그리퍼가
8초 동안 -0.2mm를 보고했습니다(오른팔 1600개, 왼팔 1598개 표본).
음수 개방 폭을 엄격히 거부하던 세 노드와 제어 실행기가 이를 유효 피드백에서 삭제했습니다.
닫힌 그리퍼의 측정값만 [-0.25mm, 0mm)에서 0mm로 정규화합니다.
목표 명령의 음수 폭, 100mm 초과, 측정값의 -0.25mm 미만은 계속 거부합니다.
추가 실물 로그에서 J5 -70.087°, -70.054°, -70.073°가 관측됐습니다.
사용자의 측정 편차 반영 요청에 따라 양팔 J5의 측정 허용폭만 0.15°로 조정했습니다.
다른 관절은 0.05°를 유지하며, 목표 명령과 계획·URDF 범위는 기존 제한을 유지합니다.
알파 목표는 양팔 모두 [0, 90, 0, 0, -70, 0]° 그대로입니다.
이 수치는 운용상 측정 허용폭이며 제조사가 보증한 엔코더 정확도가 아닙니다.
엔코더 편차와 실제 추종 오차는 아직 분리 측정하지 않았습니다.
허용폭 안의 경계 초과 피드백은 경계값으로 정규화한 뒤 충돌 계산에 사용하므로,
이 작은 각도 차이만큼의 모델 불확실성이 남습니다. 0.15°보다 큰 J5 초과는 계속 차단합니다.

설치된 드라이버에서는 피드백 변환에 0.017444, 명령 변환에 57324.840764를 사용했습니다.
이 조합은 -70° 명령을 장치에 -70.036°로 반올림해 전송하며, 그 피드백은 약 -69.999°로 표시합니다.
로컬 드라이버 복사본은 양방향에 정확한 π를 사용해 이 체계적 오차를 제거합니다.
과거 알파 정지 로그는 왼팔 관절 제한 초과만 기록하고 관절 번호·값은 기록하지 않아,
당시 정지의 직접 원인이 J5 오버슈트였는지는 확정할 수 없습니다.
이후 오류는 관절 번호·측정값·제한·초과량을 표시하고, MoveIt 오류도 세부 원인을 보존합니다.
리셋 뒤 3초 동안 잠금 해제 상태를 확인하며 자동 재리셋하지 않습니다.

이미 영점에 도착했다면 4번 `home`은 생략하고 `ready → prepare → start`로 진행합니다.
수정 후 검증은 드라이버 없는 별도 ROS 도메인에서 수행하며 실물 성공과 구분합니다.

기존 기록에서 CAN1 DOWN으로 오른팔 드라이버가 종료된 경우, 피드백 간격이 약
0.34초로 늘어난 경우, 로그를 줄인 뒤에도 MoveIt 피드백 시간 초과로 정지한 경우가
확인됐습니다. 로그 출력만이 원인이라고 확정할 수 없습니다. 또한 실제 측정된 J3의
+0.025986°가 기존 측정 허용 오차 0.01°를 넘어 유효 피드백에서 삭제되는 코드 결함이
확인되어, 측정값 경계 처리만 0.05°로 맞췄습니다. 이 값보다 큰 편차는 계속 거부하며
목표 각도와 URDF 관절 제한은 바꾸지 않습니다. 이후 J5만 위의 0.15° 측정 허용폭을 적용했습니다.

세 수신 노드는 관절 피드백을 `BEST_EFFORT / KEEP_LAST(1)`로 받습니다. 이전 센서값의
신뢰성 재전송을 기다리는 대신 최신 값으로 검사합니다. 목표 명령은 기존 RELIABLE을
유지합니다. 피드백 수명 0.15초, 양팔 시각 차이 0.05초, 충돌·관절 제한은 유지합니다.
실제 CAN/드라이버의 피드백이 이 기준을 충족하지 못하면 계속 정지하며 `ready`가 실패합니다.

정지 이유는 누락된 팔과 거부 이유 또는 양팔 피드백 나이·시각 차이를 표시합니다.
실행 전 검사는 순간적인 정상 여부가 아닌 3초의 연속 정상 여부를 확인하지만, 이후 동작의
통신 안정성을 보장하지는 않습니다. 동작 중에도 두 안전장치와 피드백 검사를 계속 적용합니다.
