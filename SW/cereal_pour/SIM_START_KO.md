CAN 활성화나 실물 드라이버 실행은 필요하지 않습니다. 이전 RViz와 시뮬 실행 터미널은 종료한 뒤 실행합니다.
실물은 같은 작업 폴더에서 완료한 시뮬 경로와 소스·모델·설정·속도가 일치해야 실행됩니다.
별도 `REAL_MOTION_HOLD_KO.md`가 남아 있는 설치본은 추가 임시 차단을 적용합니다.

실행 순서:

1. 이 작업 폴더의 ROS 패키지와 native MoveIt 계획 전용 실행 파일을 빌드합니다.
2. 물체 좌표에서 Pinocchio FK와 SciPy 수치 IK로 목표 관절각 후보를 구합니다.
   MoveIt OMPL RRTConnect가 관절 경로를 계획하며 Bullet 메시 충돌 및 별도 feasibility callback의
   거리 가드/물체/파지 물체 조건을 적용합니다. 자체 RRT나 무검사 직선 경로로 우회하지 않습니다.
3. 경로의 실행 보간 구간도 같은 조건으로 확인합니다. 계획에 실패하면 RViz 동작을 시작하지 않습니다.
4. 실행할 경로를 `model/simulation_sessions/<실행ID>/sequence.yaml`에 고정합니다.
5. `/cereal_sim` 아래에서 시퀀스 실행기 → 거리 가드 → MoveIt 메시 가드 → 이상적 가상 드라이버를 연결합니다.
   두 가드는 모두 enforce입니다. 최초 정지·초기 피드백 때문에 생긴 잠금은 영점에서 한 번만 초기화하며,
   동작 중 재리셋/재시도는 없습니다. 이후 잠금이나 상태 유실 시 표시하는 팔도 정지합니다.
6. 자동으로 영점 → 알파 → 그릇·시리얼 파지 → 붓기 → 내려놓기 → 영점 복귀를 한 번 실행합니다.
   화면에 `IDEAL GUARDED SIM: complete`, 터미널에 `SIMULATION COMPLETE`가 나오면 전체 실행 완료입니다.
   반복하려면 종료 후 같은 명령을 다시 실행합니다.

RViz는 최종 가드를 통과한 가상 피드백으로 팔을 표시합니다. 시간표만 따라 재생하는 기존 애니메이션과 다릅니다.
관성·모터 추종·오버슈트·실제 CAN 좌우/베이스 정합은 재현하지 않으므로 실물 안전 확인을 대신하지 않습니다.
MoveIt이 피하는 충돌 범위는 전달받은 모델·장면·허용 충돌 쌍과 검사 해상도에 한정됩니다.

모델은 계획/실행 모두 같은 `load_semantic`을 거칩니다. 현재 소스는 같은 팔에 속한 충돌 링크 쌍을
조립 내부로 제외하며, 양팔 사이와 로봇–기둥 사이를 검사합니다. 비인접 같은 팔의 자기충돌까지
검사하는 구현은 아닙니다. 링크별 메시를 쓰며 팔 전체를 단일 고정 STL로 합치지는 않습니다.
앞서 설명했던 자기충돌 검사 확대와 `PiperReferenceBaseLink2` 개별 복원은 철회됐습니다.
이 정책을 사용하는 팔 전용 모드의 전체 시뮬과 실물 제로 복귀가 확인됐습니다.

시뮬 완료 기록은 그 경로와 소스·모델 지문을 저장합니다. 이후 실물 사용 조건이 해결되더라도
완료한 경로와 설정이 일치해야 하며, 시뮬 완료만으로 실물 차단을 해제하지 않습니다.

정상 진행 중 목표 가속도 제한을 추가했습니다(관절 기본 20°/s², 그리퍼 20mm/s²).
가감속은 검사한 직선 관절 경로 위에서만 적용하며, 코너를 임의로 깎지 않습니다.
OMPL 직선 구간의 중복 표본은 줄이되 실제 코너는 보존합니다. 이는 목표 명령의 변화율 제어이며 모터 동역학 모델이 아닙니다.
IK는 손목 J4/J6 변화가 작은 해를 우선하고, OMPL 손목 경로는 시작/목표 범위에 기본 15° 여유로 제한합니다.
조건에 맞는 해가 없으면 실패로 끝납니다. 기존 수동 설정 파지 방향을 자동으로 바꾸지 않습니다.

로그 보기(ROS 불필요, 파일만 읽음):

```bash
python3 tools/read_session_logs.py
python3 tools/read_session_logs.py --samples --last 10
python3 tools/read_session_logs.py --json --last 5
```

- 계획 전용 MoveIt 로그: `log/planning/<계획ID>.log`
- 시뮬 실행 상세: `log/meshes_demo/diagnostics/<실행ID>/`
- `cereal_pour.jsonl`: 단계 전환과 좌우 목표/명령/측정, 두 가드 상태.
- `piper_collision_guard.jsonl`: 최초 차단, 원본 피드백·시각·정규화 오류·최소 거리·가까운 링크 쌍.
- `moveit_guard.jsonl`: 최초 차단, 충돌 링크·겹침 깊이·검사 자세(현재/예측), 원본/정규화 피드백·목표.
- 두 가드의 stop/unlock/reset은 전환 때 기록하고, 상세 상태는 최대 20 Hz로 기록합니다.
  각 파일의 `monotonic_ns`로 같은 PC의 발생 순서를 합칠 수 있습니다.
  로그는 모터 제어권을 강제로 회수하는 하드웨어 비상정지 기능이 아닙니다.

기존 사고 로그에는 이 새 JSONL이 없습니다. 기존 1초 간격 clear 기록만으로 접촉 순간까지 clear였다고
단정할 수 없으며, 감지 누락과 정지 실패 중 직접 원인은 아직 확정되지 않았습니다.
