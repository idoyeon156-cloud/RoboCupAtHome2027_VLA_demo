# CAN 이름과 실제 팔의 대응

2026-11-13 읽기 확인: `/etc/udev/rules.d`와 `/etc/systemd/network`에 PiPER CAN 이름 고정 설정이 없습니다.
기본 can0/can1 번호는 장치 등록 순서의 영향을 받으므로 물리 왼팔/오른팔 식별자로 사용하면 안 됩니다.
현재 연결의 udev 속성은 다음과 같습니다. **사고 당시 연결이나 물리 좌우를 확인한 표가 아닙니다.**

| 현재 인터페이스 | USB 시리얼 | USB 경로 |
| --- | --- | --- |
| can0 | 004E00235246571520393733 | pci-0000:00:14.0-usb-0:3.4:1.0 |
| can1 | 003400155343570F20363330 | pci-0000:00:14.0-usb-0:3.3:1.0 |

두 장치는 bytewerk candleLight USB to CAN, VID:PID=1d50:606f, gs_usb입니다.
서로 다른 고유 시리얼이 있으므로 USB 포트 위치 대신 시리얼에 이름을 묶을 수 있습니다.
왼팔 어댑터 시리얼 → can_left, 오른팔 어댑터 시리얼 → can_right로 고정하는 방식을 권장합니다.
can0/can1을 강제로 서로 바꾸는 이름 충돌도 피할 수 있습니다.

고정 규칙은 USB 어댑터를 식별합니다. 노트북 USB 포트를 바꾸어도 같은 어댑터 이름을 유지하도록
설정할 수 있지만, 어댑터에서 실제 팔로 가는 CAN 연결을 서로 바꾸면 팔 대응은 바뀝니다.
시리얼과 물리 팔의 연결을 확인·라벨링해야 합니다. 현재 번호를 근거로 좌우를 추측해 영구 등록하지 않습니다.

현재 source wrapper는 인자로 받은 인터페이스를 `left_can`/`right_can`으로 사용하며,
USB 시리얼 또는 물리 팔 위치를 검증하지 않습니다. 이름 지정만으로 물리 배치를 검증한 것이 아닙니다.
시리얼 기반 udev 규칙은 아직 설치하지 않았고 현재 CAN 상태/인터페이스 이름/모터 상태도 변경하지 않았습니다.
자동 실행 차단은 유지합니다.

참고: systemd.link 이름 지정은 https://www.freedesktop.org/software/systemd/man/latest/systemd.link.html
