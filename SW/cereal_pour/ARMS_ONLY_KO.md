# 그리퍼 명령 없이 팔 경로 확인

물체 없이, 양팔 관절 영점과 닫힌 그리퍼에서 시작합니다. 물체를 실제 파지·운반하는 모드가 아닙니다.
현재 그리퍼 피드백 -0.1mm는 기존 닫힘 측정 정규화 범위 내입니다. 개방 폭 1mm 초과는 실행기가 거부합니다.

기존 SDK, 드라이버, 실물 실행기를 먼저 종료하고 아래 명령을 사용자가 실행합니다.
이 문서를 추가하는 작업에서 실물 이동이나 새 ROS 시뮬/빌드는 실행하지 않았습니다.

## 먼저 팔 전용 시뮬

```bash
cd "/home/doyeonlee/문서/ChatGPT/VLA 공부/RoboCupAtHome2027_VLA_demo/SW/cereal_pour"
bash run_cereal_rviz.sh arms_only:=true
```

닫힌 손가락 폭 0mm로 MoveIt 경로와 보간을 새로 검사합니다. 기존 개폐 경로에서 피드백 검사만
끄는 방식이 아닙니다. 두 가드는 enforce를 유지합니다. 계획 실패 시 진행하지 않습니다.
`SIMULATION COMPLETE`로 완료한 팔 전용 경로만 실물에서 사용할 수 있습니다.
시뮬 속 물체는 경로 계획의 가상 물체입니다. 기존 목표 자세와 가상 부착/물체 충돌 조건은 유지하므로
실제 파지 없이도 계획이 불가능하면 실패합니다. 정상 파지 작업의 성공을 뜻하지 않습니다.

## 실물: 각기 별도 터미널

모든 터미널에서 위 작업 폴더로 이동합니다. CAN은 로봇 뒤에서 본 왼팔 can0 / 오른팔 can1입니다.

```bash
# 터미널 1: 모든 GripperCtrl 호출 생략. 관절 모터는 활성화합니다.
bash run_piper_driver.sh can0 can1 --arms-only
```

```bash
# 터미널 2: 팔 전용 완료 경로와 두 충돌 가드
bash run_cereal_real.sh enforce:=true geometry_confirmed:=true arms_only:=true
```

```bash
# 터미널 3: 먼저 읽기 검사
bash run_real_control.sh check
# PASS 후 계획된 영점에서 전체 실행
bash run_real_control.sh run
```

실행 도구는 드라이버 양쪽의 `cereal_gripper_commands_enabled=false`를 읽어 확인합니다.
일반 드라이버 또는 이전 드라이버이면 실행을 거부합니다. 드라이버 모드만 바꾸고 이미 실행된
프로세스를 그대로 두면 적용되지 않습니다. 팔 전용 시퀀스의 그리퍼 목표는 전부 0mm이므로
개폐 진행을 요구하지 않으며, 센서 신선도와 관절/그리퍼 범위·두 가드 검사는 유지합니다.

제로 → 알파 → 그릇·시리얼 접근 및 붓기 자세 → 알파 → 제로를 연속 실행합니다.
실제 그리퍼는 개폐하지 않습니다. 중간 실패 시 자동 리셋·재시도하지 않습니다.

소프트웨어 목표 정지 요청: `bash run_real_control.sh stop` (하드웨어 비상정지는 아닙니다).
일반 파지 모드 복귀는 두 프로세스를 종료하고 `--arms-only`와 `arms_only:=true`를 빼서 시작하며,
일반 모드 시뮬을 다시 완료해야 합니다. 그리퍼 문제 해결 전에 일반 파지 모드로 복귀하지 않습니다.

## 떨림·끊김·속도 개선 1차 변경

팔 전용 모드에서만 다음 실행 변경을 적용합니다. 일반 그리퍼 사용 모드의 보간은 유지합니다.

- 움직임 없는 개폐·가상 파지 단계와 파지 대기를 제거합니다. 알파 및 실제 유지 시간은 보존합니다.
- 정확히 같은 직선 위의 중간점만 합칩니다. 방향 전환·역방향·알파·영점·유지점은 보존하며,
  경로를 곡선으로 깎지 않습니다. 합친 선분은 기존 검사 선분들의 합집합입니다.
- 알파를 제외한 직선 구간은 5차 시간 보간을 사용합니다. 시작·끝 목표 속도와 가속도는 0이며,
  해석적 최대 속도·가속도에 따라 시간을 정해 기존 상한(관절 22.5°/s, 20°/s²)을 유지합니다.
- 중간 코너에서 속도는 0으로 만들되 불필요한 0.2초 정착 대기는 제거합니다.
  실제 측정이 도착 허용폭에 들어와야 다음 구간으로 진행합니다. 정지/유지점은 정착 대기를 유지합니다.
- 타이머의 작은 지연은 실제 경과시간으로 반영하되 한 번의 목표 진행은 최대 40ms로 제한합니다.
- 가드/추종 대기 때 목표 진행을 중단합니다. 재개는 남은 같은 선분에서 정지 상태로 다시 시작합니다.
  가드·추종 대기 진입 횟수와 이유, 보간기 이름을 `motion_progress`와 JSONL 표본에 기록합니다.

기존 완주 경로 파일의 정적 분석: 68개 구간 → 57개, 설정된 정착+유지 시간 17.6초 → 3.8초.
이는 전체 실행 시간 예측이나 실물 개선 확인이 아닙니다. 전체 경과시간은 새 보간과 실제 추종에 따릅니다.
관절 경로 모서리를 통과하는 무정지 곡선 블렌딩, MoveIt FollowJointTrajectory 컨트롤러,
드라이버 MOVE J 전송 방식 변경은 이번 범위에 포함하지 않습니다.

검증은 ROS/CAN 없이 수행한 수치·명령 차단 테스트 6개와 Python 구문 검사입니다.
실물·RViz·ROS 빌드는 에이전트가 실행하지 않았습니다. 새 소스로 위 팔 전용 시뮬 명령을
다시 실행해 `SIMULATION COMPLETE`를 확인해야 실물에서 새 실행 방식을 사용할 수 있습니다.

## 복귀 알파 감속 누락 수정

`2026-11-13_18-50-30_47840` 실물 로그에서 `return_bowl_open`이 실제 알파 도착 이동이고,
`return_alpha`는 이미 알파에 도착한 뒤의 유지 단계였습니다. 이전 코드는 단계 이름만으로 감속을
선택해 실제 복귀 접근에 마지막 5° / 1°/s 조건이 빠져 있었습니다.
목표 양팔 관절각이 알파와 일치하는지를 기준으로 감속·정착 대기·단계 제한 시간을 선택하도록 수정했습니다.
그리퍼 폭은 알파 관절 자세 식별에서 제외합니다. 원래 알파 목표와 관절/측정 한계는 유지합니다.
로그의 `alpha_destination`으로 실제 적용 대상을 확인할 수 있습니다.

같은 실행에서 최초 가드 거부는 왼팔 J5 약 -70.181°, 실행기는 -70.192° 피드백으로 정지했습니다.
단순 통신 시간 초과나 그리퍼 오류가 아니며, 제로 복귀 전 중단됐습니다. 감속 누락은 소스에서
확인한 결함이지만 실물 초과의 단독 원인 또는 수정 후 해결을 입증한 것은 아닙니다.
초기 `alpha_via_1`에는 추종 대기 진입 5회도 기록돼 있습니다. 이 반복 대기는 별도 개선 대상입니다.
수치·명령 차단·실제 실행 메서드의 복귀 감속 선택 테스트 총 8개가 통과했습니다.
이번 수정 후 ROS 빌드·시뮬·실물 실행은 하지 않았습니다.

## 완주 로그 기반 추종 대기 개선

근거는 실물 `2026-11-13_19-05-11_49772`입니다. 전체 완료까지 약 117.44초,
구간별 마지막 표본의 추종 대기 진입 횟수 합은 11회였습니다. 초기 알파 접근,
그릇 접근, 붓기 이동, 상자 복귀, 영점 복귀 등에서 반복됐습니다.
추종 오차를 초과했을 때 목표 진행을 멈추고 재가속하는 구조가 구간 내부의 끊김에
기여할 수 있습니다. 이 기록만으로 모든 실물 진동의 원인을 설명한 것은 아닙니다.

팔 전용 모드에서 추종 허용폭의 35%부터 목표 진행 시간을 점진적으로 늦춥니다.
75%에서 최소 시간 배율 0.15를 지향하며 배율 변화율도 제한합니다. 관절 추종 한계
1.5°는 유지합니다. 한계 초과 시 목표 진행을 멈추고 65% 이하로 회복한 뒤 재개해
경계 부근의 정지·재출발 반복을 줄입니다. 두 가드 차단은 그대로 적용됩니다.

시간 배율 변화에 필요한 가속도 여유를 확보하기 위해 기본 위치 프로파일에는 기존
가속도 예산의 절반을 사용하며, 나머지는 배율 변화에 배분합니다. 정상 진행의 기존
속도·가속도 상한을 높이지 않습니다. 실제 제어기의 감속·제동을 보장하는 기능은 아닙니다.
하드 차단 시 목표 진행 중단은 정상 진행의 부드러운 감속보다 우선합니다.

MoveIt 계획 경로의 중간점이 직선에서 관절별 최대 0.05° 이내로 벗어난 수치적 코너인 경우,
대체 직선 전체를 기존 `Scene.edge`로 MoveIt/Bullet·거리·물체 조건까지 다시 검사한 경우에만
중간점을 제거합니다. 손가락 폭은 같은 직선이어야 하며, 검사 실패 시 원래 경로를 유지합니다.
일반 그리퍼 모드에는 이 근사 연결을 적용하지 않습니다. 실행 중 무검사 곡선 블렌딩도 하지 않습니다.

추가 로그 필드: `tracking_ratio`, `reference_time_scale`, 기존 `pause_counts`/`pause_reason`.
검증은 ROS/CAN 없는 수치·제어 흐름 테스트 총 12개입니다. 지연 피드백 테스트는 소프트웨어
모의 입력이며 PiPER 물리 시뮬이나 실물 결과가 아닙니다. 에이전트는 새 ROS 빌드·시뮬·실물
실행을 하지 않았습니다. 소스가 바뀌었으므로 팔 전용 시뮬을 끝까지 완료한 후 실물을 실행합니다.
