# 듀얼 PiPER + 3030 세로 기둥 (별도 버전)

기존 `dual_piper.urdf` 및 `dual_piper_zero_pose_mm.stl`은 수정하지 않습니다.

## 형상과 배치

- 외곽 단면 30 × 30 mm, 길이 500 mm, 수직 방향은 원본 모델의 +Z입니다.
- 네 면의 T홈 입구는 8 mm이며, 중심 보어는 지름 6 mm의 32각형입니다.
- 특정 판매 제품을 복제한 모델이 아니라, 배치 확인을 위한 대표 형상입니다.
- 밑면 중심의 원본 STL/URDF 월드 좌표는 **(X, Y, Z) = (30, 0, 0) mm**입니다.
- URDF의 두 베이스 원점은 Y = ±87.5 mm입니다. 따라서 두 팔 사이 중앙은 Y = 0입니다.
- 베이스 메시에서 장착 구멍 중심을 피팅한 결과, X = -40 / +30 mm, Y = ±35 mm의 네 구멍을 확인했습니다.
- 사진에서 표시한 뒤쪽 구멍 줄을 **X = +30 mm 줄로 해석**했습니다. 이 줄에서 두 팔의 안쪽 구멍 중심은 (30, +52.5, 0), (30, -52.5, 0) mm이고 기둥 중심은 그 중점입니다. 반대 줄을 의도했다면 X를 -40 mm로 바꾸어야 합니다.
- 가로 프로파일의 윗면을 Z = 0으로 가정했습니다. 가로 프로파일, 체결 브래킷 및 나사는 포함하지 않았습니다.

## Fusion에서 사용

`profile_3030_500_placed_mm.step`은 월드 배치를 포함하는 단일 솔리드 STEP입니다.
원본과 동일한 좌표를 쓰는 설계에 삽입하고, 구성요소 원점을 설계 원점에 일치시키면 됩니다.
파일을 여는 것만으로 기존 로봇 설계에 합쳐지지는 않습니다. 자동 중앙 배치 기능으로 위치가 바뀌지 않았는지 확인하세요.

`profile_3030_500_placed_mm.stl` 역시 같은 위치와 mm 단위를 사용합니다.
`profile_3030_500_local_mm.stl`은 중심 X/Y = 0, 밑면 Z = 0인 URDF용 로컬 메시입니다.

## URDF의 기둥 추가 버전

`../piper_dual_description/urdf/dual_piper_with_3030_pillar.urdf`에 고정 링크 `profile_3030_pillar`를 추가했습니다.
원본 로봇 링크, 관절, 관성, 제한값 및 배치는 그대로 유지했습니다.
시각화는 홈이 있는 메시이며, **충돌 형상은 30 × 30 × 500 mm의 꽉 찬 박스**입니다.
따라서 홈 내부를 다른 물체가 통과할 수 있는 공간으로 판단하지 않습니다.
기존 launch/guard 설정은 변경하지 않았으므로 이 URDF를 명시적으로 선택해야 합니다.
이 모델만으로 실제 로봇의 충돌 방지 기능이 자동 활성화되는 것은 아닙니다.

## 두 팔과 기둥을 하나의 STL로 합치기

저장소의 기존 원본 STL을 읽어 새 STL을 만드는 스크립트를 별도로 추가했습니다.

```sh
python collision/tools/export_with_pillar.py
```

출력은 `collision/preview/dual_piper_with_3030_pillar_mm.stl`입니다.
이 스크립트는 다운로드하지 않고 로컬 원본을 읽으며, 입력 파일과 기존 출력 파일을 덮어쓰지 않습니다.
기존 로봇의 삼각형 레코드를 바이트 단위로 그대로 보존한 채 기둥을 덧붙입니다.
전체 원본 STL을 이 작업 환경에서 읽지 못했으므로 **합쳐진 전체 STL은 아직 생성하지 않았습니다.**

## 검증 범위

- 대표 기둥 메시의 외곽 치수, 길이, 일관된 면 방향 및 닫힌 표면을 검증했습니다.
- 단면적과 체적을 독립 계산하여 확인했습니다.
- 베이스 메시의 네 장착 구멍 중심을 최소제곱 원 피팅으로 확인했습니다.
- 추가 URDF에서 기존 로봇 링크와 관절 정의가 보존되는 것을 확인했습니다.
- Fusion에서 STEP을 실제로 불러오는 시험 및 팔 전체 가동 범위의 충돌 검사는 수행하지 않았습니다.
- `placement.json`, `verification.json`에 치수와 확인 결과가 있습니다.
